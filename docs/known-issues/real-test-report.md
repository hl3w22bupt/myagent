## 可能的原因

### 1. **多个 DataStore 实例仍然存在**

日志显示：
```
[DataStore] Creating global singleton instance (using global variable) - 11次
[DataStore] Returning existing global singleton (from global variable) - 2次
```

这说明 `global.__motiaDataStore` 在某些情况下被重置了。

### 2. **并发保存的竞态条件仍然存在**

可能的情况：
- `output-history-tracker` 和 `result-logger` 同时调用 `save()`
- 虽然有保存锁，但最后完成的 `save()` 会覆盖之前的更改

### 3. **sql.js 的 export() 时序问题**

```typescript
// updateTask 调用顺序
db.run(UPDATE ...)  // ← 更新内存
await this.save()    // ← export() 可能在 run() 完成前执行
```

## 结论

### 当前修复状态

**部分修复，但不完整** ✗

- ✅ 添加了保存锁机制
- ✅ 使用了真正的全局变量
- ❌ 但仍有 35% 的任务卡在 running

### 需要进一步调查

1. **为什么有些任务成功，有些失败？**
   - 成功的任务和失败的任务之间有什么区别？

2. **多实例问题的根源**
   - 为什么 `global.__motiaDataStore` 会被重置？
   - 是否有其他地方调用了 `setDataStore(null)`？

3. **并发保存的时序**
   - `output-history-tracker` 和 `result-logger` 的执行顺序
   - `save()` 是否真的被序列化？

### 建议

**修复可能需要更深入的方案**：

1. **完全禁用 output-history-tracker 的 updateTask**
   - 只让它读取，不更新数据库
   - 让 result-logger 统一负责更新

2. **添加数据库级的锁**
   - 使用 sql.js 的事务机制
   - 或者文件锁

3. **延迟保存策略**
   - 不要每次 updateTask 都立即 save
   - 使用 dirty 标记，批量保存
