# MyAgent Coding Agent 平台愿景

> 创建时间: 2026-03-02
> 状态: 探索阶段

## 核心定位

**MyAgent = 开箱即用的代码生成平台**

用户输入开发需求 → Agent 自动生成代码 → 创建 PR 供人类审查 → Merge

### 与 Claude Code 的差异

| 维度 | Claude Code | MyAgent |
|------|-------------|---------|
| 交互方式 | CLI 对话 | Web UI |
| 使用模式 | 交互式开发 | 任务式生成 |
| 文件操作 | 逐个确认/预览 | 自动批量 |
| 审查时机 | 操作前确认 | PR 事后审查 |
| 部署方式 | 本地工具 | 平台服务 |

**核心理念**: 不是复刻 Claude Code 的体验，而是打造一个**低干预、自动化**的代码生成平台。

## 扩展模型

MyAgent 通过三大扩展机制支撑各种智能体业务：

```
┌─────────────────────────────────────────────────────────┐
│          各类智能体业务应用                              │
│  (代码生成、代码审查、测试自动化、文档生成...)          │
└─────────────────────────────────────────────────────────┘
                      ↕
┌─────────────────────────────────────────────────────────┐
│     MyAgent 扩展层                                       │
│                                                         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐   │
│  │ Subagents   │  │ Skills      │  │ Hooks       │   │
│  │ (角色/流程) │  │ (独立功能)  │  │ (生命周期)  │   │
│  └─────────────┘  └─────────────┘  └─────────────┘   │
└─────────────────────────────────────────────────────────┘
                      ↕
┌─────────────────────────────────────────────────────────┐
│     基础设施层                                           │
│  (Motia 框架 + Context Manager + Agent Manager)        │
└─────────────────────────────────────────────────────────┘
```

### Subagent vs Skill 分工

| 类型 | 定义 | 示例 |
|------|------|------|
| **Skill** | 独立功能，命令式调用 | `/commit`, `/test`, `/lint`, `/review` |
| **Subagent** | 角色/流程的抽象 | `开发工程师`, `测试工程师`, `代码审查员` |

#### 典型开发流程

```
用户需求
    ↓
[开发工程师 Subagent]
    ↓
    使用各种 Skills:
    - Read / Write / Edit (文件操作)
    - /commit (提交代码)
    - /test (运行测试)
    ↓
[测试工程师 Subagent]
    ↓
    使用测试 Skills:
    - /test (运行测试)
    - /coverage (覆盖率分析)
    ↓
[代码审查员 Subagent]
    ↓
    使用审查 Skills:
    - /review (代码审查)
    - 安全检查
    - 性能分析
    ↓
创建 PR → 人类审查 → Merge
```

## 前端交互设计

### Task 详情页结构

```
┌─────────────────────────────────────────────────────────────┐
│  Task: #1234 - "实现用户登录功能"            [● Running]     │
├──────────────────────┬──────────────────────────────────────┤
│  Progress Stream     │  Artifacts (视图切换)                 │
│  ─────────────────   │  ┌─────────────────────────────────┐ │
│  [reading auth.ts]   │  │ 视图: [按轮次 ▼] [按文件树 ▼]  │ │
│  [creating login...] │  └─────────────────────────────────┘ │
│  [running tests]     │                                       │
│                      │  ┌─ 📁 src/               (文件树)  │
│  [Chat]              │  │  ├─ auth/                         │
│  > 继续添加重试功能   │  │  │  ├─ login.ts                   │
│                      │  │  │  └─ register.ts                │
│  [Send]              │  │  └─ components/                   │
│                      │  │     └─ LoginForm.jsx              │
│                      │  └─ 📁 tests/                        │
│                      │     └─ auth.test.ts                  │
│                      │                                       │
│                      │  点击文件 → 查看内容（复用现有）      │
└──────────────────────┴──────────────────────────────────────┘
```

### ArtifactsTab 视图切换

**按轮次视图** (现有):
- 下拉选择对话轮次
- 下拉选择产物
- 展示产物内容

**按文件树视图** (新增):
- 按 `path` 字段组织文件树
- 文件夹可展开/折叠
- 点击文件展示内容

## MVP 场景：代码生成

### 选择理由

用户选择 **B) 代码生成** 作为 MVP 场景，因为：
1. 需求明确，价值直接可见
2. 可以覆盖完整的开发流程
3. 容易验证效果

### 典型流程

```
1. 用户输入: "实现用户登录功能，支持邮箱和密码"

2. [开发工程师 Subagent]
   - 分析需求
   - 设计 API
   - 创建文件: src/auth/login.ts
   - 创建文件: src/auth/register.ts
   - 创建文件: src/components/LoginForm.jsx

3. [测试工程师 Subagent]
   - 创建测试: tests/auth.test.ts
   - 运行测试
   - 修复问题

4. [代码审查员 Subagent]
   - 审查代码质量
   - 检查安全问题
   - 提出优化建议

5. 创建 PR
   - 标题: "feat: 实现用户登录功能"
   - 描述: 包含所有变更和审查意见

6. 人类审查
   - 查看 PR
   - 必要时修改
   - Merge
```

### 支撑的业务类型

通过扩展 Subagents 和 Skills，MyAgent 可以支撑：

| 业务类型 | 核心需求 | 所需扩展 |
|---------|---------|---------|
| 代码生成 | 需求分析 + 代码实现 | 开发 Subagent + 各种语言 Skills |
| 代码审查 | 代码理解 + 规则检查 | 审查 Subagent + lint Skills |
| 测试自动化 | 发现测试 + 执行 + 分析 | 测试 Subagent + test Skills |
| 文档生成 | 代码理解 + 文档编写 | 文档 Subagent + template Skills |
| Bug 修复 | 日志分析 + 定位 + 修复 | 调试 Subagent + debug Skills |
| 重构 | 代码理解 + 改进方案 | 重构 Subagent + pattern Skills |

## 设计原则

1. **最小交互**: 自动化优先，减少用户操作
2. **事后审查**: 通过 PR 进行人类审查
3. **开箱即用**: 登录即用，无需配置
4. **渐进增强**: 基础功能可用，逐步添加高级功能
5. **扩展友好**: 通过 Subagent/Skill/Hook 轻松扩展
