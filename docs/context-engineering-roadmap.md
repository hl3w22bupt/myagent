## 一、整体架构

### 编排层的位置

```
┌─────────────────────────────────────────────────────────────┐
│                        Agent 层                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  PTCGenerator                                       │   │
│  │   "我要生成代码，需要知道用户的偏好和成功经验"       │   │
│  └──────────────────────┬──────────────────────────────┘   │
└───────────────────────┼───────────────────────────────────┘
                        │
                        │ 请求上下文
                        ▼
┌─────────────────────────────────────────────────────────────┐
│                      编排层 (Orchestration Layer)           │
│                                                              │
│   职责：理解需求 → 决定去哪取数据 → 组装返回               │
│                                                              │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐           │
│   │ Context  │    │ Memory   │    │ Knowledge │           │
│   │  数据源  │    │  数据源  │    │  数据源  │           │
│   └────┬─────┘    └────┬─────┘    └────┬─────┘           │
└────────┼───────────────┼───────────────┼───────────────────┘
         │               │               │
         ▼               ▼               ▼
    ┌─────────┐    ┌─────────┐    ┌─────────┐
    │ Database│    │ Database│    │  Files  │
    │(任务历史)│    │(用户画像)│    │(技能/文档)│
    └─────────┘    └─────────┘    └─────────┘
```

### 编排层的核心逻辑

**输入**：Agent 说"我需要关于这个用户的信息"

**决策过程**：
1. **理解需求** → 用户要生成视频，需要知道他的偏好
2. **决定去哪取** → 去用户画像表取 preferences
3. **取多少** → 不要全部，只要相关的（如视频相关偏好）
4. **怎么组装** → 格式化成 LLM 能理解的提示词

**输出**：一段格式化的文本，告诉 LLM "这个用户喜欢简洁风格，白天活跃"

**当前默认实现**：简单粗暴，全部取出来，不做过滤和优先级判断

**未来智能实现**：根据任务类型，智能选择相关内容

## 二、Memory 层完善

### 2.1 跨会话画像应用 ✅ **现在做**

**位置**：在 Agent 生成代码之前

```
用户发请求
    ↓
Agent 接收
    ↓
PTCGenerator 要生成代码
    ↓
【这里】→ 查看用户画像 → 调整生成策略 → 生成更符合用户偏好的代码
    ↓
返回结果
```

**逻辑**：
- 读取 userProfile 中的 preferences/habits/tags
- 把这些信息塞进给 LLM 的提示词里
- LLM 生成代码时就会考虑"用户喜欢简洁回复"

**效果**：
- 没有：所有用户收到的代码风格一样
- 有："喜欢简洁"的用户收到的代码更简洁

---

### 2.2 成功模式学习 ⏳ **仅记录，暂不使用**

**目的**：数据积累，为未来离线分析做准备

**位置**：在任务完成后

```
任务执行中
    ↓
【这里记录】→ 这次用了什么技能 + 什么参数 → 执行成功
    ↓
存入 success_patterns 表
    ↓
（暂不在线使用，仅数据积累）
    ↓
未来离线分析：
    - 提取成功经验
    - 生成新 Skill
    - 优化 Prompt
    - High level 洞察
```

**记录内容**：
- 任务模式（如："生成视频"）
- 使用的技能组合
- 参数配置
- 执行时间
- 成功次数

**未来用途**：
- 发现"哪些配置组合最容易成功"
- 提取通用成功模式
- 生成新 Skill 的参考
- 优化默认参数

---

### 2.3 失败案例记录 ⏳ **仅记录，暂不使用**

**目的**：数据积累，为未来离线分析做准备

**位置**：在任务失败时

```
任务执行中
    ↓
【这里记录】→ 这次用什么配置 → 失败了 + 错误信息
    ↓
存入 failure_cases 表
    ↓
（暂不在线使用，仅数据积累）
    ↓
未来离线分析：
    - 发现常见错误模式
    - 优化错误处理
    - 生成预警 Skill
    - High level 洞察
```

**记录内容**：
- 任务模式
- 使用的技能组合
- 参数配置
- 错误信息
- 错误类型（超时 / API 错误 / 参数错误）

**未来用途**：
- 发现"哪些配置容易失败"
- 提取常见错误模式
- 生成错误预防 Skill
- 优化系统健壮性

## 三、数据流向（完整）

```
┌──────────────────────────────────────────────────────────────┐
│                        用户使用流程                           │
└──────────────────────────────────────────────────────────────┘

用户第1次使用：生成视频
    │
    ▼
Agent：没见过这人，用默认配置
    │
    ▼
执行成功 → 记录到"成功模式"（仅记录，不使用）
    │
    ▼
记录到"用户画像"：新增标签"新用户"

────────────────────────────────────────────────────────────

用户第5次使用：生成视频
    │
    ▼
Agent：这人我认识
    │
    ├─ 编排层：查用户画像 → "喜欢简洁、白天活跃、视频偏好：1080p"  ✅ 在线使用
    ├─ 编排层：查成功模式 → （有记录，但不在线使用）
    └─ 编排层：查失败案例 → （有记录，但不在线使用）
    │
    ▼
用用户画像生成代码 → 输出更符合用户的风格
    │
    ▼
执行成功 → 更新"成功模式"记录和"用户画像"

────────────────────────────────────────────────────────────

未来离线分析（异步）：
    │
    ▼
分析 success_patterns 表
    │
    ├─ 发现："生成视频用 quality:1080p 成功率最高"
    ├─ 提取：成功经验 → 生成文档
    ├─ 优化：更新 Skill 默认参数
    └─ 洞察：用户偏好变化趋势
    │
    ▼
分析 failure_cases 表
    │
    ├─ 发现："超高清视频经常超时"
    ├─ 提取：错误模式 → 生成预警 Skill
    ├─ 优化：添加参数验证
    └─ 洞察：系统瓶颈点
```

## 五、设计原则

1. **渐进式演进**：先建框架，后填内容
2. **数据优先**：先积累数据，再考虑使用
3. **务实优先**：在线功能解决明确痛点，离线分析支持长期优化
4. **可观测**：所有记录都可追溯，方便分析
