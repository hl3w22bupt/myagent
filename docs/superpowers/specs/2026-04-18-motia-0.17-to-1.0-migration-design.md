## 4. Migration Design

### 4.1 Phase 1: Infrastructure (Batch 1)

**Scope**: Configuration, dependencies, stream configs, health check (~6 files)

**4.1.1 Dependency changes**

Remove all `@motiadev/*` packages, add:
```
motia: ^1.0.4-rc.1
iii-sdk: ^0.11.0
esbuild: (devDependency)
```

**4.1.2 motia.config.ts**

Simplify to Motia 1.0.x format (plugins auto-registered):
```typescript
import { defineConfig } from 'motia';
export default defineConfig({});
```

**4.1.3 config.yaml**

Create iii engine configuration (based on myrd's config.yaml):
- Stream module (file-based or Redis adapter)
- State module (file-based or Redis adapter)
- REST API module (port 4111)
- Queue module (builtin adapter)
- Cron module
- Observability module

**4.1.4 Stream configs**

Verify `StreamConfig` type compatibility in Motia 1.0.x. Update import paths if needed.

**4.1.5 Health check step**

Migrate `steps/health/health-check.step.ts` as first validation.

**Validation**: `npm run build` + `npm run start` + `curl /health`

### 4.2 Phase 2: API Steps (Batch 2)

**Scope**: 60 API step files

**4.2.1 Config format migration**

```typescript
// Before (0.17.x)
export const config: ApiRouteConfig = {
  type: 'api',
  name: 'skills-api',
  path: '/api/skills',
  method: 'GET',
  emits: [],
  virtualSubscribes: [],
  flows: ['metadata-api'],
};

// After (1.0.x)
export const config = {
  name: 'skills-api',
  description: 'API endpoint for querying available skills',
  triggers: [{
    type: 'http',
    method: 'GET',
    path: '/api/skills',
  }],
  enqueues: [],
} as const satisfies StepConfig;
```

Changes:
- Remove `type: 'api'`
- Move `path` + `method` into `triggers[0]`
- `emits` → `enqueues`
- Remove `virtualSubscribes`, `flows` (if unused)
- Type: `ApiRouteConfig` → `satisfies StepConfig`

**4.2.2 Handler signature migration**

```typescript
// Before
export const handler = async (request: any, { logger, streams }: any) => {
  const queryParams = request.queryParams;
  const body = request.body;
  return { status: 200, body: { ... } };
};

// After
export const handler: Handlers<typeof config> = async (context) => {
  const queryParams = context.query;
  const body = context.body;
  return { status: 200, body: { ... } };
};
```

Note: Motia 1.0.x keeps `status` (not `status_code`) and `context.query` (not `query_params`). This differs from raw iii-sdk.

**4.2.3 Batch approach**

Most API steps follow identical patterns. Process in groups:
1. Simple CRUD APIs (no streams, no emit) — bulk mechanical change
2. APIs using `streams` — verify stream API compatibility
3. APIs using `emit` — convert to `enqueue`

**Validation**: `npm run build` + curl test all `/api/*` endpoints

### 4.3 Phase 3: Event & Cron Steps (Batch 3)

**Scope**: 7 event steps + 3 cron steps (~10 files)

**4.3.1 Event step migration**

```typescript
// Before
export const config: EventConfig = {
  type: 'event',
  name: 'master-agent',
  subscribes: ['agent.task.execute', 'agent.task.chat'],
  emits: ['agent.task.completed', 'agent.task.failed'],
};

// After
export const config = {
  name: 'master-agent',
  triggers: [
    { type: 'queue', topic: 'agent.task.execute' },
    { type: 'queue', topic: 'agent.task.chat' },
  ],
  enqueues: ['agent.task.completed', 'agent.task.failed'],
} as const satisfies StepConfig;
```

**4.3.2 emit() → enqueue()**

```typescript
// Before
await emit({ topic: 'agent.task.completed', data: { ... } });

// After
await enqueue({ topic: 'agent.task.completed', data: { ... } });
```

**4.3.3 Cron step migration**

```typescript
// Before
export const config: CronConfig = {
  type: 'cron',
  name: 'UserProfileAnalysis',
  cron: '0 21 * * *',
  emits: ['user.profile.analyzed'],
};

// After
export const config = {
  name: 'UserProfileAnalysis',
  triggers: [
    cron('0 0 21 * * * *'),  // 5-field → 7-field
  ],
  enqueues: ['user.profile.analyzed'],
} as const satisfies StepConfig;
```

Cron expressions to convert:
- `0 21 * * *` → `0 0 21 * * * *` (user-profile-analysis)
- Verify other 2 cron steps

**4.3.4 Event chain verification**

Key event chains to test end-to-end:
```
agent-api → enqueue('agent.task.execute') → master-agent
master-agent → enqueue('agent.task.completed') → task-result-handler
master-agent → enqueue('agent.task.failed') → failure-handler
```

**Validation**: Submit real task, verify full execution chain completes.

## 5. Risk Assessment

| Risk | Impact | Mitigation |
|------|--------|-----------|
| Stream API parameter order change | High | Verify myrd stream usage, test early |
| `enqueue()` semantic differences from `emit()` | High | Test event chains before batch migration |
| Cron 5→7 field expression errors | Medium | Validate each expression individually |
| TypeScript compilation errors | Medium | Run `tsc` after each batch |
| `motia generate-types` compatibility | Low | Check if 1.0.x still requires this command |
| Missing `description` field on steps | Low | Add descriptions during migration |

## 6. Out of Scope

- `src/index.ts` — AgentManager initialization
